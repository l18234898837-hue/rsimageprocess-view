# 多源卫星处理前端重构设计规格

## 目标

在现有多源卫星数据处理模块内部，将“上传文件、配置参数、点击处理、下载 ZIP”的单体流程重构为可理解、可组合、可追踪的处理计划流程：用户先选择目标处理功能，系统自动补齐前置步骤，再配置对应参数并执行。

## 范围

本次仅修改前端现有多源卫星处理模块，主要范围为：

- `src/components/LeftPanel/MultiSourceSatelliteProcess.vue` 及其拆分出的子组件。
- `src/components/LeftPanel/*ParameterDrawer.vue` 中与多源步骤配置有关的适配。
- `src/features/multisource` 下的产品模板、参数、步骤定义、依赖解析、计划状态和结果展示逻辑。
- 多源模块已有的 API 调用适配，不扩展其他业务模块。
- 多源模块相关单元测试、快照测试和组件契约测试。

不包含：

- 数据源、轨道预报、普通算法分析等其他模块。
- 后端服务、数据库、任务执行引擎和 API 服务端实现。
- 本轮新增后端接口。前端通过适配层保留现有 API 调用方式，未来再接入后端的步骤计划字段。

## 统一命名

外层模块统一称为“多源卫星处理”。内部采用“通用处理能力 + 产品专属名称”的两层命名：

- 通用能力：预处理、质量控制、特征提取、RGB 融合、显著性检测、网格化、地图展示、结果打包。
- 产品专属名称作为补充，例如“MERSI 通道特征”“沿轨异常检测”“WFV 多波段融合”。

## 产品流程模型

影像产品使用共享前置流程：

```text
上传校验 -> 预处理 -> 质量控制 -> 定位/投影/网格化或裁剪 -> 标准产品
                                                               ├-> 特征提取
                                                               ├-> RGB 融合
                                                               └-> 显著性检测
```

HY-2D 使用独立的沿轨流程：

```text
上传校验 -> 沿轨解码 -> 质量过滤 -> 海面高度基线计算 -> 沿轨特征提取
                                                               ├-> 异常检测
                                                               ├-> 轨迹网格化
                                                               └-> 地图展示
```

产品不得展示不支持的能力。HY-2D 不强行套用影像产品的标准产品流程。

## 前端领域模型

步骤定义集中维护在 `pipelineDefinitions.ts`，并按产品声明可用步骤和依赖：

```ts
type PipelineType = "image" | "altimeter";
type StepKind = "system" | "target";

interface StepDefinition {
  key: string;
  title: string;
  productTitle?: string;
  kind: StepKind;
  dependsOn: string[];
  configurable: boolean;
  parallelGroup?: string;
}

interface PipelineDefinition {
  productId: string;
  pipelineType: PipelineType;
  steps: StepDefinition[];
}

interface ProcessingPlan {
  productId: string;
  selectedTargets: string[];
  resolvedSteps: string[];
  lockedPrerequisites: string[];
  parameters: Record<string, unknown>;
  invalidatedSteps: string[];
}
```

用户选择的是 `selectedTargets`，系统通过依赖解析生成 `resolvedSteps`。自动补齐步骤不能单独删除或绕过；如果其依赖目标被取消且不再被其他目标使用，则自动移除。自动步骤的参数如果存在，仍允许配置。

## 页面交互

页面采用四阶段向导：

1. 数据上传：选择产品、上传文件、显示单文件进度和整体校验结果。
2. 选择功能：只展示当前产品支持的目标功能；多选目标允许共享前置步骤。
3. 配置参数：只展开已解析流程中可配置的步骤，按步骤显示产品专属名称和校验错误。
4. 执行与结果：展示计划、步骤状态、重试、取消及结果下载。

可以返回前一阶段修改。任务创建后，产品、文件、目标功能和参数冻结；执行中只允许取消。任务完成或失败后可复制当前配置创建新任务。

执行前必须显示处理计划预览。用户不拖拽或手工改变执行顺序，顺序由依赖关系决定；无依赖关系的步骤标记为可并行。

## 参数和校验

每个步骤拥有独立参数命名空间。取消功能时暂存其参数，重新选择时恢复；切换产品时清理不兼容参数。

校验分三层：

- 上传后校验扩展名、必需文件、文件关联关系。
- 选择功能后校验依赖和产品支持关系。
- 确认处理计划时校验所有已解析步骤的参数。

修改某个前置步骤参数时，自动将其下游步骤标记为“需要重跑”，但不自动提交或执行。

## 执行和结果

前端将完整 `ProcessingPlan` 交给任务适配层；本轮不要求新增后端接口，适配层可以将计划映射到现有 `parameterSnapshot` 和任务接口。

界面同时展示：总体任务状态、步骤状态和结果状态。步骤状态至少包括等待、处理中、成功、失败、需要重跑；失败步骤支持重试，成功步骤不因其他并行步骤失败而被重复执行。

结果按功能分组，支持单项 artifact 下载和全部结果 ZIP 下载。不可下载的中间结果只展示状态，不提供下载按钮；下载按钮必须依据服务端返回的 `downloadable` 状态授权。

## 迁移原则

- 保留 `productTemplates.ts` 的文件槽位和现有产品文件校验能力。
- 保留现有产品参数文件和参数抽屉，通过步骤参数注册表接入，不在本轮重写每个参数业务规则。
- 将 `useProcessingTask.ts` 中“处理计划状态”和“远端任务执行状态”分离，避免组件直接操纵全部任务细节。
- API 变化集中在多源 API 适配层，组件不直接拼接接口请求。
- 不修改多源路由入口之外的其他模块。

## 测试策略

优先为纯函数增加测试：依赖解析、目标取消后的步骤清理、共享前置步骤、参数失效传播、产品能力矩阵和结果分组。保留并运行现有 `pnpm test:multisource`。

组件测试覆盖四阶段切换、自动步骤只读删除规则、参数错误定位、任务状态和下载按钮状态。至少验证 GF-6/FY-4B/FY-1C/FY-3H 的影像流程和 HY-2D 的沿轨流程互不混用。
